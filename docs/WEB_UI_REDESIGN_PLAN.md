# Open WebUI 本地前端重构细化方案

基线：Open WebUI `0.12.2`，上游提交
`6a18585ff4c2e5f6805f682222cfbc46dc669ef8`。

本文把已确认的产品方向细化为可以逐段实现、逐段验收的 Web 前端方案。第一轮目标是建立统一的视觉语言和聊天主路径，再扩展到设置、笔记、工作空间、管理页和独立分享页。APK 内置版本沿用同一份构建产物。

## 1. 已确认的交互决策

| 主题           | 决定                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| 手机导航       | 侧边抽屉；顶栏只保留当前会话操作，抽屉承载历史、笔记、工作空间和设置                 |
| 壁纸范围       | 全站共用一张背景；聊天、导航和浮层使用玻璃，编辑器、表格和密集内容使用更实的阅读底色 |
| 自定义层级     | 全局参数加消息、输入框单独微调；字号、行距和代码块归入阅读设置                       |
| 消息布局       | 用户消息靠右成气泡；助手回答靠左使用较宽的轻玻璃卡片                                 |
| 输入区         | 手机固定在底部；电脑保持居中宽版。附件、模型和发送/停止常驻，低频工具展开            |
| 默认背景       | 低饱和蓝灰渐变，浅色和深色各一套，不依赖外部图片                                     |
| 壁纸优先级     | 用户壁纸始终优先，模型、文件夹、新对话和恢复对话不得在渲染后期覆盖它                 |
| 登录前         | 登录、注册和找回入口仅使用默认主题，登录后再读取个人壁纸                             |
| 工作区和管理页 | 列表卡片优先，表单单列分组，复杂表格保留横向滚动                                     |
| 外观面板       | 手机底部面板，电脑右侧面板；真实页面即时预览，固定显示应用和取消                     |
| 交付节奏       | 本地编辑/推送，Actions 构建；按条件在独立测试服务预览，前端发布后同步后端镜像与 APK |

### 2.1 组件选型结论

本项目已经使用 Svelte 5、Tailwind 4、`bits-ui` 和 `svelte-sonner`。组件方案优先沿用这些依赖，只从公开 registry 取可独立维护的源码结构。

| 组件需求                   | 首选来源                                               | 采用方式                                                                               | 不直接采用的部分                                                           |
| -------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 消息行、用户气泡、助手卡片 | shadcn-svelte `Message` / `Bubble`                     | 采用 role、align、content、actions 的清晰分层，表面样式完全使用本项目 token            | 示例中的发送、流式与持久化状态                                             |
| 输入区                     | shadcn-svelte `Input Group` + Mizu `Chat Input`        | 采用 textarea、附件区、模型区和操作区的单容器分层；Mizu 的安静留白作为移动端密度参考   | 新聊天框架、语音运行时和第三方提交逻辑                                     |
| 流式滚动与目录定位         | shadcn-svelte `Message Scroller`                       | 采用“用户不在底部就不跟随、新问题靠近顶部锚定、加载旧消息保持锚点、跳回最新”的行为约定 | 第一阶段不替换现有 `Messages.svelte`，避免分支、历史和自动滚动逻辑同时迁移 |
| 推理与工具状态             | shadcn-svelte `Trace` + Mizu `Reasoning` / `Tool Call` | 使用可折叠状态行、运行中 shimmer、完成后一行摘要                                       | Open WebUI 现有工具结果和审批协议                                          |
| 附件                       | shadcn-svelte `Attachment`                             | 采用缩略图、名称、大小、上传状态和移除动作的槽位结构                                   | 新的上传 API                                                               |
| 抽屉、Sheet、Dialog、菜单  | 现有 `bits-ui` 与 `svelte-sonner`                      | 直接复用，只在项目内包一层表面样式和响应式选择                                         | 新增 Vaul、shadcn-svelte CLI 依赖或第二套设计系统                          |
| 长会话渲染                 | 当前 `content-visibility` 与现有列表实现               | 先做基准；仅当长会话滚动或内存出现可复现实测问题时再迁移                               | 未经验证的整套虚拟列表替换                                                 |
| 图标                       | 仓库已有 Open WebUI 图标集                             | 统一尺寸、线宽与触摸容器，保留品牌语义                                                 | 再引入一套 Lucide 图标造成风格混用                                         |

如果后续直接复制 shadcn-svelte 或 Mizu 的源码，按对应 MIT 许可保留来源和许可信息，并把组件固定在所选版本或提交，避免 registry 更新改变已验收样式。

### 取舍

- 不复制整套 Lobe/shadcn 视觉。它们服务于各自的排版、图标和状态模型，直接迁移会破坏 Open WebUI 的模型选择、分支和工具调用体验。
- 不做“每个消息都加一层 backdrop blur”。这是 WebView 和滚动性能的高风险点。壁纸只由一个固定背景层承载，玻璃表面使用半透明填充、细边框和高光；模糊只用于固定的导航、输入区或少量浮层。
- 不开放任意 CSS 或 JavaScript。配置只映射到预先定义的 CSS 变量和受控类名，避免样式泄漏和兼容性不可控。
- 不把聊天做成固定移动 App 模板。桌面保留宽阅读区、侧栏与快捷键；手机才启用抽屉、底部输入区和底部面板。

## 3. 视觉方向

工作名：**Mist Glass**。目标是安静、清楚、有材质感，但不抢内容焦点。

### 3.1 色彩

使用中性冷蓝作为基底，保留用户可替换的强调色。默认强调色先沿用现有蓝色，完整支持另外两套预设：

| Token                  | 浅色                      | 深色                      | 用途                                      |
| ---------------------- | ------------------------- | ------------------------- | ----------------------------------------- |
| `--owui-accent`        | `#2563eb`                 | `#6b96ff`                 | 主按钮、选中态、焦点环                    |
| `--owui-canvas-top`    | `#eaf1f7`                 | `#101722`                 | 默认渐变起点                              |
| `--owui-canvas-bottom` | `#d7e3ec`                 | `#1b2431`                 | 默认渐变终点                              |
| `--owui-ink`           | `#18212b`                 | `#f3f5f7`                 | 正文                                      |
| `--owui-muted`         | `#596675`                 | `#aab4c0`                 | 辅助信息                                  |
| `--owui-surface-rgb`   | `250 252 255`             | `18 24 33`                | 主玻璃表面色基，alpha 由透明度 token 决定 |
| `--owui-reading-rgb`   | `248 250 253`             | `14 20 29`                | 设置、代码和表单的实底表面                |
| `--owui-border`        | `rgb(255 255 255 / 0.62)` | `rgb(255 255 255 / 0.12)` | 外边框与内高光                            |

三套配色预设：

| 预设   | 强调色    | 背景氛围 | 特点                 |
| ------ | --------- | -------- | -------------------- |
| 原生蓝 | `#2563eb` | 蓝灰渐变 | 默认，清晰、熟悉     |
| 青灰   | `#1f8a83` | 青灰渐变 | 冷静、反馈状态更突出 |
| 暖砂   | `#b4653f` | 米灰渐变 | 温和、适合长时间阅读 |

正文始终使用高对比墨色；强调色只用于操作和选中状态，不渲染大段文字。

### 3.2 材质层级

定义四个表面层级。所有值都可以由外观设置覆盖，但预设只提供成组值，避免用户必须逐项调参。

| 层级             | `opacity=50` 时填充 | 模糊方式                       | 圆角 | 使用位置                     |
| ---------------- | ------------------- | ------------------------------ | ---- | ---------------------------- |
| Canvas           | 无填充              | 壁纸自身静态模糊               | 0    | 固定壁纸、默认渐变和遮罩     |
| Navigation glass | 50%                 | 固定层 `backdrop-filter: 18px` | 18px | 桌面侧栏、手机抽屉、顶部栏   |
| Content glass    | 50%                 | 不逐条过滤；透出已模糊的壁纸   | 20px | 助手回答卡片、用户气泡       |
| Control glass    | 64%                 | 固定层 `backdrop-filter: 18px` | 24px | 输入框、模型选择、菜单       |
| Reading surface  | 84%                 | 不使用实时模糊                 | 20px | 设置、表单、代码块、密集内容 |

规则：

- 同一屏幕最多出现两层可见的嵌套玻璃。
- 输入框比消息表面更实，优先保证输入内容可读。
- 代码块使用强调色淡染的阅读底色，可用 `auto`、`glass`、`opaque` 三档。
- 深色模式在壁纸上增加一个独立遮罩，默认 22%；不通过提高每个表面的不透明度来实现抗眩光。
- 消息卡片不使用逐条 `backdrop-filter`。壁纸在进入页面前完成一次静态模糊，卡片透出的背景已经柔软；卡片自身用半透明冷色填充、1px 高光边框和极淡内阴影形成玻璃材质。这样滚动长会话时不会为每条消息重复计算全屏滤镜。
- `glassBlur` 只作用于顶部栏、抽屉、输入区和少量浮层。`blur` 作用于壁纸背景层；两者不重复叠加到同一条消息上。
- 不支持 `backdrop-filter` 或启用 `prefers-reduced-transparency` 时，导航与输入区改用更实的 Reading surface，布局和其他状态不变。

### 3.3 形状、间距与字体

- 基础间距为 4dp；主布局使用 8、12、16、24。
- 全局圆角默认 20dp，可调 0–28dp；输入框圆角为全局圆角加 4dp，最大 28dp。
- 用户气泡圆角 18dp，靠近阅读流的一端为 6dp；助手卡片统一 20dp。
- 桌面侧栏宽 280px，紧凑状态 72px；聊天阅读宽度最大 880px；输入区最大 820px。
- 继续使用系统字体和仓库已有字体。代码块强制等宽，不跟随正文字体。
- 正文字号默认 15px，可调 14–19px；行距默认 1.65，可调 1.45–1.9。

### 3.4 阴影与边框

玻璃不使用大面积黑色阴影：

```css
box-shadow:
	inset 0 1px 0 rgb(255 255 255 / 0.42),
	0 8px 30px rgb(21 33 48 / 0.09);
```

深色模式降低阴影透明度，增加内轮廓，避免内容贴在壁纸上。键盘焦点始终使用 2px 强调色外环，叠在玻璃边框外。

### 3.5 Token 与透明度映射

外观设置中的百分比只作为基底，语义表面在其上做有限偏移。默认 `opacity=50` 时，内容表面保持 50%，输入区提高到 64%，代码和设置提高到 84%；调到 40% 时仍然保持可读，调到 100% 时不再透出壁纸。

```css
:root {
	/* JS 将 40..100 的本地配置收敛为 0.40..1.00 */
	--owui-glass-alpha: 0.5;
	--owui-glass-nav: clamp(0.42, calc(var(--owui-glass-alpha) + 0.02), 0.92);
	--owui-glass-content: var(--owui-glass-alpha);
	--owui-glass-control: clamp(0.56, calc(var(--owui-glass-alpha) + 0.14), 0.96);
	--owui-glass-reading: clamp(0.76, calc(var(--owui-glass-alpha) + 0.34), 1);

	--owui-blur-background: 8px; /* 壁纸处理，不依赖实时滤镜 */
	--owui-blur-control: 18px; /* 仅固定控件与浮层 */
	--owui-radius: 20px;
	--owui-border-glass: rgb(255 255 255 / 0.58);
	--owui-highlight-glass: rgb(255 255 255 / 0.46);
	--owui-shadow-glass: rgb(21 33 48 / 0.09);
	--owui-duration-fast: 120ms;
	--owui-duration-base: 180ms;
	--owui-ease-standard: cubic-bezier(0.22, 1, 0.36, 1);
}
```

- `opacity`、`blur`、`glassBlur`、`radius` 在浏览器或原生设置层校验一次，然后由根节点统一写入 CSS 变量。
- 组件的单独覆盖只改变该表面的 alpha、圆角和允许的固定模糊，不复制整套 `backdrop-filter`。
- 主题切换只替换 `--owui-*` 和 `dark` 状态，不刷新页面、不重算用户设置、不重建 WebView。
- 正文、按钮文字和焦点环使用单独的高对比 token，不跟随玻璃透明度变化。

## 5. 组件规范

### 5.1 顶部栏与导航

- 高度 52px，桌面和手机均使用。位于内容之上，不跟随消息滚动。
- 左侧：菜单按钮、会话标题或页面标题。标题单行截断，更多信息放入悬停/详情。
- 右侧：目录、搜索（适用页面）、页面操作。所有图标按钮最小 40px，手机触摸区域至少 44px。
- 顶部栏本身使用 Navigation glass；不再使用渐隐白/黑蒙层模拟背景。
- 侧栏分三块：品牌与新建；搜索和固定入口；可滚动历史。用户菜单固定底部。
- 当前项使用 10% 强调色填充和左侧 3px 指示条；悬停只增加表面亮度。
- 手机抽屉打开时焦点被困在抽屉，关闭后焦点回到菜单按钮。

### 5.2 会话列表与目录

- 会话条目高度至少 44px；标题一行，时间或摘要只作为次级信息。
- 目录使用同一套底部抽屉：顶部搜索、已加载范围提示、问题摘要列表。
- 当前问题使用强调色左线和更实的表面；点击后平滑滚动，保留用户的滚动锚点。
- 非当前分支不显示为目录项；历史加载或分支变化时重新计算并清空过期请求。
- 空状态说明“只显示已加载消息”，不提供隐式加载全历史的按钮。

### 5.3 用户消息气泡

```text
                                      ┌─────────────────────────┐
                                      │ 用户正文                 │
                                      │ 附件                     │
                                      └─────────────────────────┘
                                      时间  分支 12/3  编辑 复制  更多
```

- 最大宽度：桌面 72%，手机 84%；短消息自动收缩。
- 使用 Content glass，背景中带极淡强调色，不使用纯强调色铺满。
- 附件位于正文下方，行内附件保持圆角，图片最大高度受视口约束。
- 消息操作默认弱化；桌面悬停或键盘聚焦出现，手机放在消息下方单独操作行。
- 编辑、删除、分支切换和流式状态继续由原 `UserMessage` 逻辑处理，样式层不复制状态。

### 5.4 助手回答卡片

● 模型名                                          状态 / 用时
┌────────────────────────────────────────────────────────────┐
│ 正文、标题、列表、表格                                     │
│                                                              │

- 卡片横跨阅读区的可用宽度，头像或模型标识放在卡片标题行。
- 推理、工具调用和来源使用可折叠状态条；进行中显示 `shimmer`，完成后收起成一行。
- 代码块使用 Reading surface，标题栏与代码区分离；复制按钮保持常驻。
- 表格保留横向滚动；不隐藏列。图片、iframe、终端和 Canvas 使用实底容器。
- 消息操作在桌面可悬停出现，在手机始终可触达；所有操作字号不小于 12px。

### 5.5 输入区

```text
┌────────────────────────────────────────────────────────────┐
│ [附件缩略图 / 文件]                                         │
│ 输入正文，可自动增高至 240px                                │
│                                                            │
│ ＋  工具 / 技能     模型选择器  ⌄     语音   发送 / 停止    │

```

- 单层 Control glass 容器，正文区没有第二层边框。
- 附件和排队消息显示在正文上方，不把输入框越推越高超过视口。
- 常驻按钮只保留附件、工具入口、模型、语音与发送/停止。低频能力进入工具菜单。
- 生成中发送按钮变为停止按钮，按钮形状和位置不变，避免误触。
- 手机输入区宽度为视口减 24px，底部加 `env(safe-area-inset-bottom)`；桌面最大宽 820px。
- 输入区状态错误仍使用原有 toast/对话框，不在浮层中重新实现业务逻辑。

### 5.6 外观面板

桌面使用右侧 400px inspector；手机使用从底部升起的可滚动 sheet。面板始终是当前页面上的一层，页面保持可交互的预览区域。

分组：

| 分组 | 控件                                               |
| ---- | -------------------------------------------------- |
| 预设 | 原生蓝、青灰、暖砂、自定义                         |
| 背景 | 默认渐变、本地图片、裁切位置、缩放、遮罩、静态模糊 |
| 玻璃 | 全局透明度、模糊、圆角、强调色                     |
| 组件 | 用户消息、助手卡片、输入框的透明度/模糊/圆角覆盖   |
| 阅读 | 明暗模式、正文大小、行距、代码块风格               |

面板底部固定：`恢复此项`、`取消`、`应用`。面板顶部显示当前服务来源与“仅保存在此设备”。

预览事务：

1. 打开面板时复制当前生效配置，不写入持久化存储。
2. 每个控件更新一份草稿变量，真实聊天页面立即变化。
3. 点击应用才写入配置并提交到原生/浏览器存储。
4. 取消、返回、失去服务或页面切换时恢复快照。
5. 预览自身不刷新页面、不重建输入框，不改变 WebSocket 和草稿。

### 5.7 抽屉、对话框和菜单

- 桌面对话框保持居中，最大宽度按内容分类；移动端改为底部 sheet 或全高 sheet。
- 设置面板左侧导航在手机上变成顶部下拉/分段选择，滚动内容保持固定操作栏。
- Dropdown 和 Select 仍由现有 portal 渲染；玻璃 token 挂在根节点，不能只在聊天容器内定义。
- 菜单项最小高度 40px，危险操作使用红色文字；不把删除等操作放进相邻主按钮的误触区域。

### 5.8 笔记、工作空间与管理页

- 列表页：手机显示单列卡片，每张卡片包含标题、更新时间、状态和主要操作；桌面使用紧凑网格或表格。
- 编辑页：背景使用 Reading surface；富文本、代码、终端和 iframe 内容保持实底。
- 设置表单：按“基础、行为、高级”分组，常用项先显示，高级项可折叠。
- 用户、模型、知识库表格保留所有列；手机提供横向滚动和粘性首列，不把数据字段藏在纯图标中。
- 日历保留月/周/列表结构；自动化保留调度状态和运行记录，仅调整页面壳与卡片，不改交互模型。

### 5.9 登录、分享和嵌入

- 登录、注册和找回入口先使用默认渐变与统一玻璃表单，不读取私人壁纸。
- 分享页使用默认主题或分享者允许的显式主题；只读消息复用统一消息卡片。
- 嵌入聊天和编辑器 iframe 不继承任意背景透明度，外层容器使用实底或强阅读表面。
- 主题切换只更新 CSS 变量，不重建 WebView 或 iframe。

### 5.12 组件状态

| 状态             | 视觉与交互                                                 |
| ---------------- | ---------------------------------------------------------- |
| 默认             | 中性表面、1px 半透明边框、无大面积阴影                     |
| hover            | 表面亮度或强调色 tint 增加约 4–6%，不改变布局尺寸          |
| focus-visible    | 2px 强调色外环，外环不裁切；任何操作都必须有键盘焦点态     |
| pressed          | 最多 1px 缩放或亮度变化，不使用夸张弹跳                    |
| selected/current | 10% 强调色填充、左侧 3px 指示条或清晰图标状态              |
| disabled         | 降低对比度并禁用指针，但保留可读文字；不伪装成普通可用控件 |
| loading          | 原位显示 spinner、骨架或 shimmer；布局尺寸不变             |
| streaming        | 光标/状态点轻量呼吸；用户滚动后立即停止自动跟随            |
| error            | 红色图标与文字共同提示；输入和法律文本不会被红色表面盖住   |
| dragging/drop    | 使用 2px 强调色虚线边框和浅色 tint；拖拽结束恢复原样       |

动效只用于状态变化：面板进出 180–220ms，菜单淡入 120ms，消息出现 120–160ms。使用统一 ease token，尊重 `prefers-reduced-motion`；线程滚动和流式正文本身不播放逐字入场动画。

### 5.13 层级与 portal 规则

```text
背景层                   z-index: 0
页面内容                  z-index: 10
顶部栏 / Composer dock   z-index: 20
抽屉 / Inspector          z-index: 40
Dialog / 命令面板         z-index: 50
Toast                     z-index: 60
```

- 外观相关 CSS 变量定义在 `document.documentElement`；不把变量只挂在聊天页容器上。
- Dropdown、Select、Popover、Dialog 和 Toast 即使 portal 到 `body`，也必须继承同一套变量。
- 顶部栏和输入区是布局的一部分，不使用覆盖正文的 `position: fixed`；手机键盘出现时由容器高度和 `dvh` 处理。
- 打开全屏移动面板时锁定背景滚动；桌面 Inspector 不锁正文滚动，便于实时预览。
- 一个页面只能有一个活动 Composer dock。新对话、已有对话和嵌入聊天分别挂载同一组件，不复制输入状态。

### 5.14 会话滚动约定

本轮保留 `Messages.svelte` 现有的历史、分支和流式数据逻辑，只把滚动行为整理成同一份可测试约定：

1. 用户距离底部 48px 内时，流式正文继续跟随；离开底部后立即停止自动跟随。
2. 用户发送新问题时，把该轮用户消息放在顶栏下方约 16–24px；助手回答从该消息下面展开。
3. 加载更早历史时，以加载前的可视消息为锚点，不跳到顶部也不跳到最新。
4. 切换分支时继续尊重现有的“分支变化后滚动”设置；不因样式重排改变判断阈值。
5. 用户选中文字、打开链接、操作菜单或键盘导航时，不抢占滚动位置。
6. 用户离开底部且仍有新内容时显示 `ScrollToLatest`；点击后恢复跟随并到达最新消息。
7. 目录定位按已加载消息 ID 执行；消息 ID 不存在、服务或会话代次变化时丢弃旧请求。
8. 只有在真实长会话基准证明现有 `content-visibility` 不足时，才评估 shadcn-svelte `MessageScroller` 或虚拟列表；第一阶段不重写滚动所有权。

## 8. 状态、可访问性与性能

### 可访问性

- 正文与表面的对比度至少 4.5:1；大字号至少 3:1。
- 图标按钮都有可见焦点和 `aria-label`。
- 抽屉/对话框支持 Escape、焦点圈定和焦点返回。
- 状态不只通过颜色表达；流式、成功、错误同时提供文字。
- 尊重 `prefers-reduced-motion`；关闭动画后保留 80–120ms 淡入，不做位移。

### 性能

- 背景是固定单层的层级，避免滚动时重新计算全屏模糊。
- 消息卡片只使用半透明背景，不逐条 `backdrop-filter`。
- 图片先压缩并限制长边，壁纸在显示前完成静态模糊；滚动过程不运行动画滤镜。
- CSS 变量只在根节点更新，避免每个消息组件重新解析设置。
- 主题切换不刷新、不重建 WebView；消息目录结果只在当前连接代次和页面实例内有效。

## 9. 配置模型

只保存外观与阅读参数，不保存聊天内容、登录凭据或服务响应。推荐 schema：

```ts
type SurfaceOverride = {
	opacity?: number; // 40..100
	blur?: number; // 0..30
	radius?: number; // 0..28
};

type AppearanceSettings = {
	version: 2;
	enabled: boolean;
	preset: 'native-blue' | 'teal-slate' | 'warm-sand' | 'custom';
	theme: 'system' | 'light' | 'dark';
	accent: string;
	wallpaper:
		| { kind: 'gradient'; value: 'default' | 'blue' | 'teal' | 'sand' }
		| { kind: 'local-image'; assetId: string; cropY: number; scale: number };
	glass: {
		opacity: number;
		blur: number;
		radius: number;
		scrim: number;
	};
	components: {
		userMessage?: SurfaceOverride;
		assistantMessage?: SurfaceOverride;
		composer?: SurfaceOverride;
	};
	reading: {
		fontSize: number;
		lineHeight: number;
		codeTone: 'auto' | 'glass' | 'opaque';
	};
};
```

- 所有数字进入应用前做类型检查、有限值检查与区间收敛。
- 旧 schema 1 字段映射到新字段，未知字段丢弃。
- 配置按规范化的服务 origin 隔离；本地渐变或测试样例需要单独命名空间。
- Web 版图片进入 IndexedDB；Android 版图片进入应用私有目录。两者都不能上传到服务端。
- 配置对象不包含服务地址的凭据、浏览器历史、聊天文本或 token。
- 开启关闭是显式根属性，例如 `html[data-owui-appearance='on']`；关闭后不留下内联样式。

当前 Android 外观配置中已有 `opacity`、`blur`、`glassBlur`、`radius`、`codeTone`、`fontSize` 和 `lineHeight`。前端适配层按下面的含义读取，不另造一套同名但行为不同的设置：

| 现有字段                  | 前端语义                       | CSS 映射                                                  |
| ------------------------- | ------------------------------ | --------------------------------------------------------- |
| `opacity`                 | 全局玻璃基底透明度             | `--owui-glass-alpha`                                      |
| `blur`                    | 壁纸静态模糊                   | `--owui-blur-background`                                  |
| `dim`                     | 壁纸遮罩                       | `--owui-wallpaper-scrim`                                  |
| `glassBlur`               | 固定导航、输入区和浮层的模糊   | `--owui-blur-control`                                     |
| `radius`                  | 全局圆角基底，按组件类型设上限 | `--owui-radius`                                           |
| `background` / `image`    | 渐变或本地壁纸来源             | 背景层与 `data-wallpaper`                                 |
| `codeTone`                | 代码块使用自动、玻璃或实底     | `data-code-tone`                                          |
| `fontSize` / `lineHeight` | 聊天正文排版                   | `--owui-reading-font-size` / `--owui-reading-line-height` |

本地背景只影响已登录的应用页面。使用自有图片后，官方现有的文件夹、模型、服务默认背景不得在渲染后期覆盖它；外观模块关闭时才恢复 Open WebUI 原有的背景优先级。登录前的认证页、公开分享页和嵌入页继续使用各自的默认背景，不读取私人图片。

实现时先建立三个接缝，再替换视觉：

1. `AppearanceProvider` 在首次绘制前后把经过校验的 CSS 变量、明暗状态和 `data-owui-*` 写到根节点；变量不依赖聊天页是否已挂载。
2. `Chat.svelte` 的聊天页骨架统一使用顶栏、可伸缩内容区、底部输入区三行布局；已有对话、新对话和嵌入聊天复用同一 `ComposerDock`，页面只渲染一个输入实例。
3. 消息组件只接管外表面、间距和动作行；消息 ID、分支关系、流式内容和历史加载继续由现有组件提供。

`bits-ui` 已在依赖中，可直接复用其 Drawer、Dialog、Popover、Select 和 Tooltip 原语。`svelte-sonner` 继续承担通知。第一阶段不新增 Compose、React、Vaul、Mizu 或另一套设计系统依赖。

## 11. 分段交付

### 第零段：组件基线预览

- 在仅本地开发可访问的组件预览路由中展示顶部栏、侧栏条目、用户气泡、助手卡片、输入区、抽屉、菜单、设置行和代码表面。
- 同一页切换浅色、深色、背景开/关和 375/1024 两档宽度，便于先判断玻璃质感、密度、圆角和按钮样式。
- 这一页只验证 token 与组件，不接入聊天请求，也不进入生产导航；确认后再把组件接入真实页面。
- 组件预览和真实聊天页都使用同一套 token 文件；禁止为预览另写一套独立样式。

### 第一段：视觉基底与聊天主路径

交付内容：

- 默认渐变、浅深色 token、固定背景层。
- 桌面侧栏和手机抽屉外壳。
- 聊天顶部栏、欢迎区、输入区、用户气泡、助手卡片和消息操作。
- 外观配置的 schema、默认值、CSS 变量映射和假配置/测试样例。
- 共用 `ComposerDock`，覆盖已有对话、新对话和嵌入聊天，避免输入框重复或位置不一致。
- 本地背景优先级接缝：外观关闭时保留官方背景逻辑，外观开启时个人壁纸覆盖文件夹和模型背景。

验收：

- 375、600、768、1024、1440 五档截图。
- 浅色、深色、长消息、代码块、附件、新对话和恢复对话；新对话背景不得短暂消失或回退到白底。
- 输入草稿、滚动、流式生成和停止不被布局修改破坏。
- 手机键盘出现后最后一条消息仍可滚到输入区上方，安全区不遮挡发送按钮。

### 第二段：外观面板与真实预览

- 实现桌面 Inspector、手机底部 sheet、应用/取消快照。
- 接入壁纸、透明度、模糊、圆角、强调色、组件覆盖和阅读设置。
- 增加旧 schema 迁移、非法值、错误恢复和样式撤销测试。

### 第三段：导航与设置

- 对话目录、筛选和消息定位。
- 设置页、对话历史、笔记和工作空间的导航统一。
- 键盘、触摸、焦点和返回顺序验收。

### 第四段：全站页面

- 笔记编辑器、工作空间、管理表格、频道、线程、日历、自动化、实验场。
- 登录、分享和错误页使用默认主题的独立覆盖。
- 完成页面覆盖矩阵，不允许把“聊天页完成”等同于全站完成。

### 第五段：APK 内置与发布

- 将已确认的前端构建产物接入 APK，固定源码提交和资源摘要。
- 先做一次 Android 诊断，随后沿现有 Android-only PR、快检和发布流程交付。
- 发布说明分别记录浏览器验证、自动检查和设备验证；不宣称未完成的真机验收。

## 12. 统一验收清单

### 视觉

- 浅色和深色均有完整默认渐变，不出现白闪或全屏纯色替换。
- 玻璃只出现在导航、聊天卡片、输入区和浮层；代码、表格、编辑器保持可读。
- 长标题、长模型名、长消息、多附件和代码都有稳定布局。
- 375px 手机没有横向页面滚动；复杂表格在自己的容器内横滑。

### 行为

- 打开外观预览后，页面可继续滚动和操作；取消恢复全部原值。
- 应用外观不刷新页面、不清空输入、不重建 WebView、不改变服务连接。
- 切换模型、文件夹、新对话和恢复对话时个人壁纸保持优先。
- 切换主题只更新客户端控件和聊天样式，不改服务端用户设置。
- 目录只读取当前已加载分支，过期结果被丢弃。

### 回归

- 登录态、OAuth 返回、历史加载、分支切换、停止生成、附件上传预览与下载。
- 笔记自动保存/选区、工作空间权限、管理确认、频道线程、日历时区和自动化调度。
- 桌面快捷键、手机侧滑、系统返回、键盘遮挡、前后台恢复。

## 13. 后续 UI 修改的人工验收标准

下列清单继续用于后续 UI 修改，不表示当前仍停留在首个 PR 前。可在具备运行条件的开发机器或独立测试环境查看真实页面；本地 5173 仅是一种方式：

1. 组件基线在 375px 和桌面宽度、浅色和深色下均完成视觉确认；按钮、滑杆、输入区和玻璃层级没有风格混用。
2. 聊天首页和至少一个已有会话在桌面宽度下呈现新的壳层、输入区和消息层级。
3. 375px 模拟宽度下打开侧栏抽屉和底部面板，页面不横向溢出。
4. 浅色、深色各截图一次；代码块、长消息和流式状态不丢失操作。
5. 新对话 → 已有对话 → 新对话的背景保持一致；切换模型和文件夹不覆盖个人壁纸。
6. 设置页、笔记和工作空间至少各打开一次，确认没有被全局变量破坏。
7. 在一次包含至少 30 条消息、代码块和附件的历史中手动滚读并继续流式生成，确认没有明显掉帧、位置跳动或逐条模糊卡顿。
8. `npm run check`、相关单元测试和静态构建通过后，再整理成前端 PR。

当前阶段不把未完成的笔记编辑器、管理表格、频道和日历称为“已重构完成”。
